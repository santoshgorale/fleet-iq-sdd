# Checklist — UX Designer (`spec.ux`)

## Journey
- [ ] Primary journey written as numbered steps, with surfaces named
- [ ] The user can tell they succeeded — the success state is explicit
- [ ] Entry points identified, including deep links if they exist

## The states that break products
- [ ] Empty
- [ ] Loading
- [ ] Partial data
- [ ] Error
- [ ] Permission denied
- [ ] Offline or degraded connectivity

Each with what the user sees *and* what they can do next.

## Accessibility
- [ ] Full keyboard path, with focus order
- [ ] Contrast target stated
- [ ] Screen-reader labelling for interactive elements
- [ ] Smallest supported viewport named
- [ ] Standard being held to is written down

## Content
- [ ] Real copy for every user-visible message, including errors
- [ ] No placeholder text presented as final
- [ ] Error messages tell the user what to do, not just what failed

## Clean
- [ ] Prototype links supplement written decisions rather than replacing them
- [ ] No `TODO(sdd)` markers in the Experience section
